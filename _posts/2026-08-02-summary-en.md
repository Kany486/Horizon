## [RipGrep musl binaries intermittently segfault on very large searches](https://github.com/BurntSushi/ripgrep/issues/3494) ⭐️ 8.0/10

A bug report on ripgrep&\#x27;s GitHub issue tracker documents that ripgrep binaries built against musl libc occasionally crash with a segfault when performing very large searches. Community analysis suggests the root cause involves interactions between the musl allocator \(mallocng\) and kernel behavior. This issue matters because ripgrep is a widely used high-performance search tool, and musl-based static binaries are popular for deployment on Alpine Linux and in containers. Understanding and fixing this crash could improve reliability for users relying on musl builds, while the discussion also highlights general allocator pitfalls in multithreaded applications. The crash appears only with musl libc, not with glibc, pointing to allocator-specific behavior. The community investigation references a detailed analysis at dfoxfranke/ripgrep-3494-analysis and a related Linux kernel patch, indicating the segfault may stem from kernel interactions under heavy memory pressure. The bug is intermittent and tied to very large searches, making it hard to reproduce deterministically.

hackernews · throwaway2037 · Aug 1, 12:34 · [Discussion](https://news.ycombinator.com/item?id=49133889)

**Background**: musl is a lightweight C standard library designed for Linux, commonly used to produce fully static binaries and as the libc for Alpine Linux. The default musl allocator, mallocng, has known performance and scalability issues under multithreaded contention, which can lead to unexpected behavior in memory-intensive applications. RipGrep is a fast, recursive-search tool written in Rust; Rust binaries statically link a libc via the target environment, so musl targets are a common choice for portability.

## [Study Probes Symmetry Inside KataGo&\#x27;s Go-Playing Neural Network](https://www.reddit.com/r/MachineLearning/comments/1vcrki2/how_symmetric_are_the_insides_of_a_go_network_r/) ⭐️ 8.0/10

The developer of the open-source Go program KataGo published a study analyzing how symmetric the internal representations of a superhuman Go neural network are, despite training only with stochastic rotation and reflection augmentation. The study&\#x27;s writeup was largely AI-assisted but with detailed human direction. This work contributes to interpretability research by examining whether neural networks naturally learn orientation-invariant representations in a fully symmetric domain. Understanding how symmetry emerges or fails to emerge can inform data augmentation strategies and architectural design for other domains. The study explores a model trained with only stochastic 8-fold spatial augmentation, meaning each training batch is randomly rotated or reflected, yet the Go rules are fully symmetric. One finding was unexpected, and the code is linked from the project&\#x27;s GitHub.io page.

reddit · r/MachineLearning · /u/icosaplex · Aug 1, 16:18

**Background**: KataGo is an open-source computer Go program that uses deep learning and self-play reinforcement learning in a manner inspired by AlphaZero. Go&\#x27;s rules are invariant under rotations and reflections of the board, but neural networks are not explicitly constrained to respect this symmetry. Data augmentation is commonly used to encourage invariance, but it is stochastic here, so the network must potentially learn orientation-specific features. This study investigates how much the internal representations truly become orientation-independent.
